Everything end-to-end, no backend.

No servers, no API keys, no stubbed buttons — a city simulation inside the shared core moves drivers, matches rides, and completes trips while both frontends run the real domain logic.

🏙️

A city that drives itself

A simulation engine in packages/shared runs ambient cars across a synthesized San Francisco — ride matching, movement along routes, dispatch offers, scheduled-ride activation — ticking at 8× real time so demos finish fast.

💸

Real fares, real surge

Five ride products (X, XL, Comfort, Black, Green/EV) with per-product fares and ETAs, deterministic surge per location and 10-minute demand bucket, promo codes, and receipts that break down fare, surge, and tip.

🔁

Rider and driver, both seats

Request, track, chat, and rate from the rider seat — then flip to driver mode: go online, accept offers on a 12-second countdown, run the trip to arrival, and watch the 78%-share earnings ledger grow.

🧩

One codebase, three platforms

Types, fares and surge, places, the engine, stores, and the server API contract all live in packages/shared. iOS, Android, and web consume identical engine events — so they behave the same.

📱

Expo mobile, Next.js web

apps/web is Next.js 15 (App Router, React 19, react-leaflet + OpenStreetMap — no API key). apps/mobile is Expo SDK 54 with react-native-maps for iOS and Android.

✅

Typechecked, end to end

One npm workspace: npm run typecheck covers shared + web + mobile, a node:test suite runs the domain and engine lifecycle (13 tests), and npm run web:build ships a production web build.

  • 01Multi-stop trips — add up to two stops; the car pauses at each, and fares and ETAs cover the full route
  • 02Real device GPS on every platform — pickup defaults to your actual location, with a simulated San Francisco fallback
  • 03Scheduled rides that auto-start, plus trip history with full receipts, ratings, and tipping
  • 04A safety toolkit — one-tap 911, live trip sharing with trusted contacts, and a public /trip/:id share page
  • 05Payments end-to-end: cards, cash, and Avenue Wallet — plus in-trip chat with quick replies

How it fits together.

One TypeScript workspace. The shared domain core powers both frontends, and everything runs locally against createMockApi() — swap in a real ServerApi client and nothing in the UI changes.

🧠

packages/shared

The domain core — types, fares and surge, places, the city simulation engine, Zustand stores, and the server API contract both apps run against.

🌐

apps/web

Next.js 15 web app (App Router, React 19) with rider and driver mode, live maps via react-leaflet + OpenStreetMap, and shareable /trip/:id pages.

📱

apps/mobile

Expo (React Native) app for iOS and Android — expo-router, react-native-maps, AsyncStorage, real GPS with a simulated SF fallback.
